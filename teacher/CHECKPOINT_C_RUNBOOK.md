# Checkpoint C — Runbook docente

## Finestra

Settimana 33 — 3 ore flessibili.

## Principio

Il Checkpoint C **non introduce nuovi prerequisiti**. È uno spazio di chiusura annuale per finalizzazione, recupero, evidence e enrichment controllato.

## Priorità docente

Usare la settimana nell'ordine seguente:

1. recuperare outcome core non ancora stabili;
2. completare/rifinire il capstone OOP;
3. raccogliere evidence mancanti;
4. correggere bug e regressioni;
5. migliorare leggibilità/responsabilità/composizione;
6. solo dopo, enrichment.

## Capstone: evidence minima

Verificare che il prodotto finale mostri, quando pertinente:

- analisi del problema;
- classi/istanze con responsabilità riconoscibili;
- `__init__`, attributi e metodi coerenti;
- stato valido/invarianti semplici;
- composizione/collaborazione tra oggetti oppure motivazione del perché non serve;
- struttura dati appropriata al dominio;
- test/checklist con edge case;
- spiegazione delle scelte.

Non premiare complessità accidentale, numero di classi o quantità di righe.

## Recupero mirato

Se uno studente non è pronto al capstone completo, assegnare un recupero focalizzato su una competenza osservabile, per esempio:

- scelta `for`/`while` e trace;
- funzione pura + `return`;
- alias/copia;
- scelta list/tuple/set/dict;
- lookup/frequenze;
- file testo/pathlib;
- classe/istanza/metodi;
- composizione.

L'evidence può essere un esercizio corretto, un debug spiegato, un trace o una piccola parte del progetto rifatta correttamente.

## Conduzione possibile — 3 ore

### 0–20 min

- stato individuale;
- checklist competenze/progetto;
- scelta del target personale della sessione.

### 20–90 min

- lavoro sul capstone o recupero;
- docente usa domande diagnostiche e review del codice;
- un problema alla volta;
- regression check dopo ogni correzione.

### 90–135 min

- refactoring leggero;
- nomi/responsabilità/composizione;
- completamento test/evidence.

### 135–165 min

- breve presentazione/spiegazione a campione o peer review guidata.

### 165–180 min

- chiusura annuale;
- evidence mancanti;
- eventuale enrichment/futuro percorso.

## Romeo

Romeo può essere usato come variante del capstone soltanto se `romeo-sim` è certificato nel Classroom Environment. Il core deve restare completabile senza hardware e con capstone generico equivalente.

## AI

Se consentita in questa fase, usarla solo per review/debug con obbligo di verifica, test e spiegazione. Non accettare una modifica che lo studente non sa descrivere.

## Gate

Checkpoint C completato non significa automaticamente `Content Pack approved` o `ready for classroom`; questi restano gate di delivery separati.
